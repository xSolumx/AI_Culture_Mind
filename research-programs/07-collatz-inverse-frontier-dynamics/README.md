# Programme 07: Collatz inverse-frontier dynamics

## Scope

A standalone exact-computation programme about the inverse graph of the
accelerated odd Collatz map

\[
T(n)=\frac{3n+1}{2^{\nu_2(3n+1)}}.
\]

For an odd target `h`, the proposal defines `alpha(h)` as the least odd
multiple of three whose accelerated orbit reaches `h`, defines
`E(N) = max alpha(h)` over odd `h <= N`, and calls a target hard when it sets a
new `alpha` record. The programme is independent of Spin(8), triality, neural
memory, and state-space modelling.

## Core Questions

1. Is `alpha(h)` well-defined for every odd target under the stated source and
   reachability convention?
2. Does the inverse-coverage envelope satisfy `E(N) / N -> 32/9`?
3. Are all sufficiently large hard targets generated by the valuation word
   `(1,4)`, or do arbitrarily large exceptional record families exist?
4. Can admissible positive inverse cylinders be encoded by a finite-state
   weighted affine semigroup whose extremal cycles and offsets control the
   record frontier?

## Proven / Established Results

The following algebra follows directly from the stated inverse-step
definition and has been checked independently of the reported computation:

- An inverse step with valuation `a` is the affine map
  `x -> (2^a x - 1) / 3`, restricted by integrality, positivity, oddness, and
  reachability conditions.
- A word `(a1, ..., ar)` composes to a rational affine map with nominal slope
  `2^(a1 + ... + ar) / 3^r`.
- The two-step word `(1,4)` gives the candidate source
  `(32h - 5) / 9`; for odd targets this branch is integral with odd
  intermediate/source values when `h = 1 mod 18`.
- Consequently its candidate source-to-target ratio is
  `32/9 - 5/(9h)` and tends to `32/9` along admissible targets.

These identities do **not** prove that this candidate is the minimal source,
that it sets a record, or that it dominates asymptotically.

## Open Claims

- The reported universal bound `alpha(h) < (32/9) h` and the claimed optimality
  of `32/9` within a finite positive-cylinder cover
- The lower bound `liminf E(N)/N >= 32/9` is open 
- Eventual `(1,4)` dominance is a stronger open conjecture and is not required
  by the envelope limit.
- A literature/novelty review for equivalent inverse-record formulations is
  still required.

## Dependencies

- The intended proof programme needs exact integer/rational arithmetic,
  explicit residue and positivity conditions, a reproducible ascending-source
  scanner, and finite-cover certificates.
- Programme 01 may provide reusable affine composition, scan, and compiler
  patterns. Max-plus or weighted-automaton language may guide analysis, but it
  is not currently a theorem.
- No result from any Spin, Clifford, sensing, memory, or SSM programme is
  mathematical evidence for a Collatz claim.
- The new \(\mathbb Q(\sqrt2)\) scalar-field and Clifford-signature layers do
  not alter this programme. A future exact affine certificate may reuse generic
  rank or field utilities, but such code reuse would not transfer a theorem.

## Non-claims

- The inverse-frontier conjecture is not the classical Collatz conjecture and
  would not by itself prove forward convergence to one.
- A maximizing nominal slope is not sufficient: affine offsets, residue-class
  occupancy, positivity, minimality, and actual record occurrence also matter.
- Computation through a finite bound cannot prove eventual dominance.
- This programme is not a Schur decomposition, triality construction, or
  neural-memory application.

## External Claims Not Imported

No external Collatz code, scan output, or finite-cover proof is imported here.
Any claims from outside this checkout remain out of scope until independently
replayed with exact inputs and provenance.

## Reproduction in this checkout

The bounded control is
[`src/collatz_inverse_frontier.py`](src/collatz_inverse_frontier.py), with
tests in [`tests/test_collatz_inverse_frontier.py`](tests/test_collatz_inverse_frontier.py).
Run it with:

```powershell
$env:PYTHONPATH='src'
python src/collatz_inverse_frontier.py `
  --target-limit 1000 `
  --source-limit 100000 `
  --verification-limit 10000 `
  --max-steps 100000 `
  --output artifacts/collatz_inverse_frontier_bounded_20260810.json
python -m unittest discover -s tests -v
```

The scanner uses exact global path merging and a transition cache. Once a
smaller source has completed a deterministic suffix, later sources stop at
that merge state because every target on the suffix has already received its
smallest possible source. A deliberately slower reference scanner remains in
the module, and tests require exact output equality. On the recorded
workstation, the optimized `target_limit=10000, source_limit=1000000` request
took about 0.12 s versus about 3.9 s for the reference implementation; this
is a local Python timing, not a hardware-general complexity claim.

The recorded result reproduces `alpha(19)=33` through
`33 -> 25 -> 19`, verifies the exact `(1,4)` candidate
`67 -> 101 -> 19`, finds 15 finite hard records among the reached targets up
to 1000 in the small control, and certifies all 10,000 bounded verification
inputs by descent or path merge. In the 10,000-target run, all 5,000 odd
targets up to 10,000 were reached before the source boundary. The `(1,4)`
candidate at `h=19` is deliberately not reported as minimal: the earlier
`(2,2)` source `33` is smaller. This is exactly the minimality distinction the
asymptotic programme must preserve.

The artifact is
[`collatz_inverse_frontier_bounded_20260810.json`](artifacts/collatz_inverse_frontier_bounded_20260810.json).
The ten-thousand-step artifact is
[`collatz_inverse_frontier_10000_steps_optimized_20260810.json`](artifacts/collatz_inverse_frontier_10000_steps_optimized_20260810.json).
Both are finite control artifacts; neither imports an unverified `10^10` scan
or finite-cover proof.

## Five-minute wall-clock scan

The timed runner is
[`src/run_timed_scan.py`](src/run_timed_scan.py). It keeps source order exact,
but caps the path-merge cache so a long run cannot turn into an unbounded
Python-set allocation. Once the cap is reached, it retains the already-recorded
alpha minima and continues with local cycle detection; the fallback changes
performance only, not source-order minimality.

The recorded five-minute run used:

```powershell
python src/run_timed_scan.py `
  --duration-seconds 300 `
  --target-limit 100000000 `
  --source-limit 10000000000 `
  --max-steps 10000 `
  --max-cached-states 1000000 `
  --verification-limit 10000 `
  --output artifacts/collatz_timed_5min_20260810.json
```

It scanned 10,610,377 odd multiples of three, reached 35,147,827 targets,
and recorded 21,480 hard records before the wall-clock deadline. The bounded
verification control again certified all 10,000 integers. The run stopped by
time, not by target completion; unreached targets remain unknown.

Artifact: [`collatz_timed_5min_20260810.json`](artifacts/collatz_timed_5min_20260810.json).

## Forward-Collatz bounded verifier

For finite forward checks on the classical Collatz map, use
[`src/classical_collatz_scan.py`](src/classical_collatz_scan.py):

```powershell
$env:PYTHONPATH='src'
python src/classical_collatz_scan.py `
  --limit 100000 `
  --max-steps 10000 `
  --output artifacts/collatz_forward_bounded_20260810.json
```

This produces a finite certificate of starts in `[1, limit]` that reach 1 within
`max_steps` plus explicit counterexamples if any bounded run fails to certify a
start. It is intentionally limited to finite evidence and does not prove the
global conjecture.
