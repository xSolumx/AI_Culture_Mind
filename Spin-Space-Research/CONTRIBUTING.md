# Contributing

**Research author and maintainer:** Hayden Austin

Thank you for wanting to contribute to the Spin-Space Research component of
AI Culture Mind. This document explains how contributions are licensed, how to
provide proper attribution, and reporting channels for conduct or licensing
concerns.

## License for contributions

This repository is licensed under the Apache License, Version 2.0
(`Apache-2.0`). Unless you explicitly state otherwise, a contribution
intentionally submitted for inclusion is provided under the same terms.

If you are contributing third-party content (code, images, text, datasets, or
weights), verify that it can be distributed in the intended repository context
and include its source, attribution, and licence. Do not label third-party
material as Apache-2.0 unless its rightsholder actually grants those terms.

## How to add license and attribution headers

- Preserve existing copyright and license headers in files you modify.
- For new files, include a brief one-line header (see example below) and a fuller header if appropriate.

Example one-line header (add at the top of new source files):

> Copyright (C) 2026 Hayden Austin — licensed under Apache-2.0

Recommended multi-line header for source files:

"""

## Attribution for third-party content

If you include third-party code or assets, add a short note indicating the original source and license, for example:

> "This file includes code from <project/name> licensed under <LICENSE>. See <URL> for details."

Record the third-party licence exactly and keep any required notices or source
boundaries intact.

## Reporting license or attribution concerns

If you believe a contribution violates the project's Apache-2.0 terms, a
third-party licence, or an attribution requirement, report it using the
repository's "Report: License or Attribution" issue template or email
haydaust@gmail.com. Include file paths and commit SHAs where possible.

## Pull request expectations

- Keep PRs focused and small where possible.
- Significantly large or controversial changes may be discussed in an issue before a PR is opened.
- Link to related issues and provide testing notes or examples when applicable.

## Code style and testing

Follow the repository's existing style and testing patterns. If there is no automated test framework, provide manual instructions for how maintainers can reproduce and verify the change.

## Questions

If you're unsure about licensing, attribution, or how to contribute safely, email haydaust@gmail.com before submitting a major change.
