# Contributing

Thank you for wanting to contribute to the Solum Triality research repository. This document explains how contributions are licensed, how to provide proper attribution, and reporting channels for conduct or licensing concerns.

## License for contributions

This repository is licensed under the GNU Affero General Public License v3 (AGPL-3.0). By submitting pull requests, issues, or other contributions to this repository, you agree to license your contributions under the same AGPL-3.0 terms.

If you are contributing third-party content (code, images, text), ensure that the content's license is compatible with AGPL-3.0 and include attribution and license information in the contribution.

## How to add license and attribution headers

- Preserve existing copyright and license headers in files you modify.
- For new files, include a brief one-line header (see example below) and a fuller header if appropriate.

Example one-line header (add at the top of new source files):

> Copyright (c) 2026 Solum — licensed under AGPL-3.0-or-later

Recommended multi-line header for source files:

"""
Copyright (C) 2026 Solum

This file is part of the Solum Triality project and is licensed under the GNU Affero General Public License v3.0 or later (AGPL-3.0+).
For full license text see: https://www.gnu.org/licenses/agpl-3.0.en.html
"""

## Attribution for third-party content

If you include third-party code or assets, add a short note indicating the original source and license, for example:

> "This file includes code from <project/name> licensed under <LICENSE>. See <URL> for details."

Make sure the third-party license is compatible with AGPL-3.0.

## Reporting license or attribution concerns

If you believe a contribution violates the project's AGPL-3.0 license, or if attribution is missing or incorrect, please report it using the repository's "Report: License or Attribution" issue template or by emailing haydaust@gmail.com. Include file paths and commit SHAs where possible.

## Pull request expectations

- Keep PRs focused and small where possible.
- Significantly large or controversial changes may be discussed in an issue before a PR is opened.
- Link to related issues and provide testing notes or examples when applicable.

## Code style and testing

Follow the repository's existing style and testing patterns. If there is no automated test framework, provide manual instructions for how maintainers can reproduce and verify the change.

## Questions

If you're unsure about licensing, attribution, or how to contribute safely, email haydaust@gmail.com before submitting a major change.
